# Program Studio 사용설명서 유지 규칙

이 디렉터리는 사용자에게 보이는 프로그램 기능과 사용설명서가 서로 어긋나지 않도록 유지하기 위한 개발 규칙을 설명합니다.

## 사용자용 설명서 위치

실제 사이트의 사용설명서 화면은 `guide.html`이며, 프로그램별 상세 내용은 아래 파일이 원본입니다.

- 인쇄물 사전 검토: `js/program-manuals/print-checker.js`
- 스마트 인쇄배치: `js/program-manuals/smart-print-layout.js`
- PDF배치: `js/program-manuals/pdf-editor.js`
- PDF편집: `js/program-manuals/pdf-editor-advanced.js`
- PDF 유틸리티: `js/program-manuals/pdf-suite.js`

공통 렌더링은 `js/program-manuals/app.js`, 공통 디자인과 자동 시연 애니메이션은 `css/program-manuals.css`에서 담당합니다.

## 기능 변경 시 반드시 같이 할 일

사용자가 보거나 조작하는 기능을 추가·삭제·변경하면 같은 Pull Request에서 해당 프로그램의 설명서 파일도 수정해야 합니다. 단순한 문구 한 줄 추가가 아니라 실제 사용자에게 필요한 사용 순서, 설정 의미, 주의사항, 문제 해결 내용까지 기능 변화에 맞춰 갱신합니다.

특히 아래 변경은 설명서 갱신 대상입니다.

1. 버튼, 체크박스, 입력값, 메뉴, 모드 추가·삭제·이름 변경
2. 업로드 가능한 파일 종류나 크기 제한 변경
3. 자동 배치·페이지 처리·회전·잘라내기·양면 처리 등 동작 방식 변경
4. 저장·불러오기 대상이나 저장 한도 변경
5. 결과 PDF 생성 방식이나 출력 권장 설정 변경
6. 기존 기능의 기본값 변경
7. 사용자가 알아야 할 오류 조건이나 제한 변경

내부 리팩터링, 테스트 코드만의 변경, 주석 정리처럼 사용자 동작에 전혀 영향을 주지 않는 변경은 설명서 갱신이 필요하지 않습니다.

## 자동 시연 갱신

기능 흐름이 바뀌면 해당 설명서의 `demo` 배열도 확인합니다. 자동 시연은 실제 작업 순서를 요약해야 하므로 화면 흐름이 바뀌었는데 예전 순서를 보여주면 안 됩니다.

## PR 검사

`.github/workflows/manual-sync.yml`이 프로그램 관련 소스 변경과 해당 설명서 파일 변경을 비교합니다. 사용자 기능 소스가 바뀌었는데 설명서가 함께 수정되지 않으면 PR 검사가 실패합니다.

검사는 `scripts/check_manual_sync.py`가 담당합니다. 새 프로그램을 추가하면 이 스크립트의 프로그램-설명서 매핑과 `js/program-manuals/catalog.js`에도 새 프로그램을 등록해야 합니다.

## 작성 기준

설명서는 개발자 설명이 아니라 실제 사용자의 작업 순서로 작성합니다.

- UI에 표시되는 한국어 명칭을 그대로 사용합니다.
- “왜 필요한지”와 “언제 사용하면 안 되는지”를 함께 설명합니다.
- 인쇄·양면·재단처럼 장비에 따라 결과가 달라질 수 있는 기능은 시험 출력 권장을 적습니다.
- 자동 처리 기능은 결과를 최종 확인해야 한다는 점을 명시합니다.
- 이미 삭제된 기능이나 아직 구현되지 않은 기능을 현재 기능처럼 설명하지 않습니다.
- 설명서의 `updated` 날짜를 실제 수정 날짜로 갱신합니다.
