# Program Studio 사용설명서 유지 규칙

이 디렉터리는 사용자에게 보이는 프로그램 기능과 사용설명서가 서로 어긋나지 않도록 유지하기 위한 개발 규칙을 설명합니다.

## 사용자용 설명서 위치

메인 프로그램 카드에는 `사용설명서` 버튼이 있으며, 버튼을 누르면 현재 화면 위 레이어에서 해당 프로그램의 상세설명서를 확인합니다. 설명서 데이터는 버튼을 누른 뒤 필요한 프로그램만 지연 로딩합니다.

별도 상세설명서 화면은 `manuals/index.html`이며, 프로그램별 상세 내용은 아래 파일이 원본입니다.

- 인쇄물 사전 검토: `js/program-manuals/print-checker.js`
- 스마트 인쇄배치: `js/program-manuals/smart-print-layout.js`
- PDF배치: `js/program-manuals/pdf-editor.js`
- PDF편집: `js/program-manuals/pdf-editor-advanced.js`
- PDF 유틸리티: `js/program-manuals/pdf-suite.js`

공통 설명서 렌더링은 `js/program-manuals/app.js`, 메인 카드 레이어는 `js/program-manuals/home-modal.js`, 별도 설명서 화면 디자인은 `css/program-manuals.css`, 메인 레이어 디자인은 `css/program-manual-home-modal.css`에서 담당합니다.

## 기능 변경 시 반드시 같이 할 일

사용자가 보거나 조작하는 기능을 추가·삭제·변경하면 같은 Pull Request에서 해당 프로그램의 설명서 파일도 수정해야 합니다. 단순한 문구 한 줄 추가가 아니라 실제 사용자에게 필요한 사용 순서, 설정 의미, 주의사항, 문제 해결 내용까지 기능 변화에 맞춰 갱신합니다.

특히 아래 변경은 설명서 갱신 대상입니다.

1. 버튼, 체크박스, 입력값, 메뉴, 모드 추가·삭제·이름 변경
2. 업로드 가능한 파일 종류나 크기 제한 변경
3. 자동 배치·페이지 처리·회전·잘라내기·양면 처리 등 동작 방식 변경
4. 저장·불러오기 대상이나 저장 한도 변경
5. 결과 PDF 생성 방식이나 출력 권장 설정 변경
6. 기존 기능의 기본값 변경
7. 사용자가 알아야 할 오류 조건이나 제한 변경

순수 내부 리팩터링, 테스트 코드만의 변경, 주석 정리처럼 사용자 동작에 전혀 영향을 주지 않는 변경은 원칙상 설명서 내용 변경이 필요하지 않습니다. 다만 자동 검사는 사용자 영향 여부를 코드 의미까지 판별할 수 없기 때문에 프로그램 구현 경로가 수정되면 보수적으로 해당 설명서 파일도 같은 PR에서 확인하도록 요구합니다. 실제 기능 설명이 변하지 않았다면 설명서의 내용을 검토한 뒤 `updated` 날짜와 유지 확인 문구 등 최소한의 동기화 변경으로 검사에 포함시킵니다.

## 설명서 구성

설명서는 탭이나 자동 시연 없이 한 화면에서 순서대로 읽을 수 있는 상세설명서로 유지합니다. 사용자가 프로그램 카드에서 바로 열어도 이해할 수 있도록 다음 내용을 중심으로 작성합니다.

- 작업 전 확인사항
- 사용 순서
- 상세 기능과 설정 의미
- 주의사항과 결과 확인 방법
- 자주 발생하는 문제와 해결 방법
- 필요한 용어 설명

## PR 검사

`.github/workflows/manual-sync.yml`이 프로그램 관련 소스 변경과 해당 설명서 파일 변경을 비교합니다. 사용자 기능 소스가 바뀌었는데 설명서가 함께 수정되지 않으면 PR 검사가 실패합니다.

검사는 `scripts/check_manual_sync.py`가 담당합니다. 새 프로그램을 추가하면 이 스크립트의 프로그램-설명서 매핑과 `js/program-manuals/catalog.js`에도 새 프로그램을 등록해야 합니다. `scripts/validate_program_manuals.py`는 설명서 5종의 등록, 필수 섹션, 메인 프로그램 카드의 레이어형 설명서 버튼, 별도 상세설명서 화면, 프로그램 화면의 문맥형 설명서 연결까지 별도로 검사합니다.

## 작성 기준

설명서는 개발자 설명이 아니라 실제 사용자의 작업 순서로 작성합니다.

- UI에 표시되는 한국어 명칭을 그대로 사용합니다.
- “왜 필요한지”와 “언제 사용하면 안 되는지”를 함께 설명합니다.
- 인쇄·양면·재단처럼 장비에 따라 결과가 달라질 수 있는 기능은 시험 출력 권장을 적습니다.
- 자동 처리 기능은 결과를 최종 확인해야 한다는 점을 명시합니다.
- 이미 삭제된 기능이나 아직 구현되지 않은 기능을 현재 기능처럼 설명하지 않습니다.
- 설명서의 `updated` 날짜를 실제 수정 날짜로 갱신합니다.
