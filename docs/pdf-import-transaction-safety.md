# PDF 파일 추가 임시검사와 실패 복구

## 목적

페이지가 많은 편집 작업에서 새 PDF 하나가 손상됐다는 이유로 기존 파일과 편집 내용을 처음부터 다시 만들지 않도록 한다.

## 처리 순서

1. 사용자가 선택한 업로드 모드(`새 작업`, `연속 추가`, `비연속 추가`)를 작업 시작 시 고정한다.
2. 새 파일을 현재 `parsedPages`와 `uploadedFiles`에 넣지 않은 상태로 PDF.js에서 연다.
3. 모든 페이지를 순서대로 읽고 기존과 동일한 0.9배 썸네일을 임시 배열에 만든다.
4. 모든 페이지가 성공한 경우에만 파일 배열과 페이지 배열을 새 배열로 한 번에 교체한다.
5. 새 작업의 용지 자동 감지와 기존 작업 초기화도 성공한 뒤에만 적용한다.
6. 실패하면 임시 캔버스와 PDF 문서를 해제하고 기존 작업을 유지한다.

## 오류 안내

- 실패한 파일명과 가능한 경우 실패한 원본 페이지 번호를 표시한다.
- 기존 작업이 있으면 `기존 작업은 그대로 유지됩니다`라고 안내한다.
- 오류 표시에서 같은 파일을 다시 시도할 수 있다.
- 여러 파일을 선택한 경우 실패한 파일은 반영되지 않고 다음 파일 처리를 계속할 수 있다.

## 원자적 반영 범위

성공 전에는 다음 값을 변경하지 않는다.

- `parsedPages`
- `uploadedFiles`
- `previewCanvases`
- `fileNupMap`
- 용지 크기와 가로·세로 방향
- 업로드 모드
- 현재 미리보기 HTML

커밋 중 UI 갱신에서 예외가 발생해도 위 상태와 페이지 ID 순서를 이전 값으로 복원한다.
