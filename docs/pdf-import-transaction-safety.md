# PDF 파일 추가 임시검사와 실패 복구

## 목적

페이지가 많은 편집 작업에서 새 PDF 하나가 손상됐다는 이유로 기존 파일과 편집 내용을 처음부터 다시 만들지 않도록 한다. 기존 대용량 최적화를 유지해 임시검사 때문에 브라우저 메모리 사용량이 더 커지지 않게 한다.

## 처리 순서

1. 사용자가 선택한 업로드 모드(`새 작업`, `연속 추가`, `비연속 추가`)를 작업 시작 시 고정한다.
2. 새 파일을 현재 `parsedPages`와 `uploadedFiles`에 넣지 않은 상태로 PDF.js에서 연다.
3. 모든 페이지를 임시 배열에서 검사한다.
4. 모든 페이지가 성공한 경우에만 최종 페이지 ID를 발급하고 파일·페이지 배열을 한 번에 반영한다.
5. 새 작업의 용지 자동 감지와 기존 작업 초기화도 성공한 뒤에만 적용한다.
6. 실패하면 임시 캔버스와 PDF 문서를 해제하고 기존 작업을 유지한다.

## 대용량 최적화 유지

기존 `upload-fix.js`와 같은 기준을 사용한다.

- 25페이지 이상 또는 30MB 이상: 0.42배 축소 썸네일과 900px 최대 변 사용
- 80페이지 이상 또는 80MB 이상: 0.28배 축소 썸네일 사용
- 누적 120페이지 초과: 자동 미리보기 최소화
- 300페이지 이상: 모든 실제 캔버스를 만들지 않고 번호 목록용 경량 페이지를 사용

300페이지 이상인 파일도 각 페이지 객체와 기본 크기 정보는 순서대로 확인하지만 실제 썸네일 캔버스는 경량 번호 상자로 대체한다. PDF.js는 작업자 없는 로드를 먼저 시도하고 실패하면 일반 작업자 방식으로 다시 연다.

## 오류 안내

- 실패한 파일명과 가능한 경우 실패한 원본 페이지 번호를 표시한다.
- 기존 작업이 있으면 `기존 작업은 그대로 유지됩니다`라고 안내한다.
- 오류 표시에서 같은 파일을 다시 시도할 수 있다.
- 여러 파일을 선택한 경우 실패한 파일은 반영되지 않고 다음 파일 처리를 계속할 수 있다.

## 원자적 반영 범위

성공 전에는 다음 값을 변경하지 않는다.

- `parsedPages`
- `uploadedFiles`
- `previewCanvases`
- `fileNupMap`
- 용지 크기와 가로·세로 방향
- 업로드 모드
- 전역 페이지 ID 순서

임시검사 중 사용자가 다른 편집 작업으로 새 페이지 ID를 사용해도 가져오기 실패가 ID를 과거 값으로 되돌리지 않는다. 최종 커밋 중 UI 갱신에서 예외가 발생하면 커밋 직전 상태만 복원한다.

## 미리보기 복원

롤백 시 `innerHTML` 문자열로 미리보기를 재생성하지 않는다. 기존 `previewScroll`의 실제 자식 노드를 보관했다가 그대로 다시 연결하므로 캔버스 픽셀 내용이 유지된다.
