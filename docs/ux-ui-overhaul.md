# Program Studio UX/UI 전면 개편

## 목표

기능 처리 로직은 보존하면서 사용자가 처음 진입한 순간부터 결과 파일을 저장할 때까지 화면 구조, 정보 위계, 조작 밀도, 모바일 대응, 접근성과 초기 로딩 경험을 하나의 제품 경험으로 통일한다. 개편 중 발견되는 실제 오류, 상태 불일치, 단축키 충돌, 접근 제어 경쟁 조건과 회귀 테스트 문제도 함께 수정한다.

## 전체 진단

### 1. 화면마다 디자인 규칙이 다름
홈, 로그인, 관리자, PDF 편집기, PDF 검사, 디자인 편집기, 문서 편집기, 이미지 편집기가 각각 별도 색상·간격·버튼 크기·모서리·그림자 규칙을 사용했다.

### 2. 편집기 조작 밀도가 높음
특히 디자인 편집기에는 작은 설명·필드·상태 텍스트가 많고, 문서/이미지 편집기도 기능이 늘수록 왼쪽 패널 밀도가 높아지는 구조였다.

### 3. 작업영역 확보와 빠른 이동이 어려움
편집기 왼쪽 패널이 작업영역을 계속 차지하고, 다른 도구로 이동하려면 홈을 거쳐야 하는 경우가 많았다.

### 4. 기능 중심 배치라 초보 사용자가 작업 순서를 알기 어려움
PDF, 디자인, 문서, 이미지 편집기는 기능은 많지만 어떤 순서로 사용해야 하는지 한눈에 보이지 않았다.

### 5. 스타일·보정·부트 코드가 분산됨
여러 HTML/CSS/JS에 화면 보정 규칙이 분산되어 있고 오래된 호환 코드가 남아 있어 새 기능을 붙일 때 회귀 위험과 불필요한 초기 실행 비용이 있었다.

## Phase 1 — 공통 UX 기반 · 완료

- 공통 색상, 여백, 모서리, 그림자, 포커스 규칙 추가
- 홈 카드와 내비게이션 가독성 개선
- 로그인 화면 데스크톱 2단 레이아웃
- 관리자 카드·메트릭·입력창 밀도 정리
- PDF/디자인/문서/이미지 편집기 기본 가독성 개선
- 편집기 `작업 패널` 접기/펼치기 및 상태 기억
- `Ctrl/Cmd + K` 전역 빠른 실행
- 입력 중 빠른 실행 단축키가 편집을 방해하지 않도록 충돌 방지
- 중첩 `/index.html` 경로를 홈으로 잘못 판별하던 오류 수정
- 키보드 포커스 표시와 `prefers-reduced-motion` 대응

## Phase 2 — PDF 편집기 작업 흐름 · 완료

- `파일 → 페이지·배치 → 꾸미기 → 출력` 4단계 흐름
- 기본 기능과 고급 설정 분리
- 출력 직전 페이지 수·용지·방향·N-up 요약
- 최종 PDF 저장 영역 하단 고정
- 런타임 모듈 실패/처리 오류 표시 및 `미리보기 재생성 / 새로고침 / 닫기` 복구
- 썸네일의 잘못된 `클릭=제외` 안내를 실제 동작인 `클릭=미리보기 이동`으로 수정
- compact shell 로딩 순서에 따라 패널 접기 버튼이 사라질 수 있던 경쟁 조건 수정
- 명시적 workflow `refresh()`는 즉시 반영하고 일반 상태 변경만 배치 갱신하도록 정리
- 기존 PDF 렌더·저장 함수는 교체하지 않음

## Phase 3 — 디자인 편집기 작업 흐름 · 완료

- `구성 → 편집 → 정리 → 출력` 4단계 흐름
- 기존 빠른 구성, 선택 요소 편집, 스마트 정리, 인쇄 품질·안전 검사와 연결
- 최종 PNG/PDF 출력 영역을 항상 찾기 쉬운 위치로 고정
- 런타임 진단 상태와 자동 저장 상태를 작업 흐름에서 바로 확인
- `고급 도구`와 선택 요소 `세부 설정`이 같은 저장 키를 사용해 서로 열림/닫힘 상태를 덮던 오류 수정
- 정상적인 취소 작업이 런타임 오류로 기록되는 문제 필터링
- 단계 클릭 후 활성 표시가 늦게 변경되던 UX 지연 수정
- 기존 300DPI 출력 및 최종 인쇄검사 파이프라인은 그대로 사용

## Phase 4 — 문서·이미지 편집기 작업 흐름 · 완료

### 문서 편집기
- `시작 → 작성 → 검토 → 출력` 4단계 흐름
- 현재 단어 수·글자 수·A4 방향·자동 저장 상태를 한 카드에서 표시
- 자동 저장 실패/경고 상태를 즉시 표시
- 사이드바 하단에 `지금 저장 / 인쇄·PDF 저장` 고정 작업 영역 추가
- 새 출력 UI는 기존 `saveNowBtn`, `printBtn`, `DocumentEditorApp` API를 그대로 재사용
- 기존 본문 편집·표·이미지·자동 저장·인쇄 로직을 교체하지 않음

### 이미지 편집기
- `불러오기 → 자르기·크기 → 보정·배경 → 저장` 4단계 흐름
- 이미지 크기·작업 횟수·오류 상태를 상단 흐름 카드에서 확인
- 저장 설정 영역을 하단 고정하고 현재 크기·형식·품질 요약 표시
- 오류 발생 시 `다른 이미지 열기 / 원본 복원`으로 기존 기능을 바로 재사용
- 숫자/설정 입력창에서 `Ctrl/Cmd+Z`가 이미지 전체 실행취소로 전달되던 단축키 충돌 방지
- PNG/JPEG/WebP 출력 및 배경 제거·자르기 핵심 함수는 교체하지 않음

## Phase 5 — 홈·관리자·PDF 검사 · 완료

### 홈
- 실제 사용 가능한 핵심 도구 5종을 `바로 작업 시작` 영역에 모아 표시
- 프로그램명·작업명 검색
- 즐겨찾기와 최근 사용 도구를 브라우저에 기억
- `/` 키로 홈 검색에 즉시 포커스
- 기존 카테고리/프로그램 카드 렌더링은 그대로 유지

### 관리자
- 대시보드 `최근 가입 회원`은 읽기 전용으로 변경해 실수로 승인/중지하는 위험 제거
- 회원 목록에 선택 체크박스와 화면 전체 선택 추가
- 다중 회원 승인·중지·FREE·PRO 변경 지원
- 일괄 변경 전 대상 인원 확인창 표시
- 개별 `이용 중지`도 확인 후 실행
- 기존 회원 목록 렌더링과 Firestore 데이터 구조는 교체하지 않음

### PDF 인쇄 검수
- 검사 결과를 `문제 → 확인 필요 → 정상` 순으로 자동 정렬
- 전체/문제/확인/정상 개수 표시 및 즉시 필터링
- 문제 카드와 확인 카드의 시각 우선순위 강화
- 기존 검사/보안/도구 처리 함수는 교체하지 않음

### 배포 안정성
- 공통 UX 자산 캐시 버전을 `20260828-2`로 갱신
- Phase 5 홈·관리자·PDF 검사 전용 Chrome smoke를 품질 게이트에 추가

## Phase 6 — 남은 화면·레거시 경로·최종 접근성 · 완료

### 로그인
- 서비스 이용 순서를 `로그인 → 승인 확인 → 작업 시작`으로 명확히 안내
- 로그인/회원가입 탭에 `tablist`, `tab`, `aria-selected`, 키보드 포커스 상태 적용
- 비밀번호 보기/숨기기 버튼 추가
- 360~480px에서 2단 레이아웃을 1단으로 단순화하고 입력·버튼 조작 영역 확보

### 승인 대기
- 상태 안내 영역에 `role=status`, `aria-live=polite` 적용
- 승인 대기·이용 중지·오류 상태를 카드 상태와 시각 피드백으로 연결
- 승인 완료 시 홈으로 이동한다는 후속 흐름 안내 추가
- 400px 이하에서 상태 확인/로그아웃 버튼을 한 열로 배치

### 이용안내·약관·개인정보
- 문서 제목을 접근성 이름으로 연결하고 본문 바로가기 링크 추가
- `h2` 구조를 기반으로 자동 목차 생성
- 데스크톱 고정 목차, 모바일 가로 스크롤 목차 제공
- `인쇄 · PDF 저장` 버튼 및 인쇄 전용 레이아웃 추가
- 긴 문서의 모바일 여백·제목·본문 폭을 정리

### 책표지·디자인 진입 경로
- `/perfect-binding-cover/` 및 구형 표지 링크가 `mode=cover` 외 기존 쿼리·해시 값을 잃지 않도록 수정
- 통합 디자인 셸이 최초 진입 URL의 `mode / preset / paper / orientation / w / h / fold` 값을 읽어 실제 작업 화면으로 전달
- 기존 기본 표지 경로와 `UnifiedDesignShell.stage` 계약은 유지해 기존 회귀 테스트와 호환

### 구형 `tools/` 경로
- PDF 편집기·PDF 검사·표지 호환 주소를 `noindex` 처리
- JavaScript 이동과 함께 접근 가능한 본문 링크를 제공
- 검색 조건과 해시가 있는 기존 링크는 새 주소까지 보존

### 모바일·접근성·배포 검증
- 로그인·승인대기·법적 문서를 실제 Headless Chrome `360x800` 크기로 검증
- 가로 오버플로, 탭 ARIA, 비밀번호 토글, 라이브 상태, 목차, 본문 바로가기, 인쇄 동작을 자동 검사
- 공통 UX 자산 캐시 버전을 `20260828-3`으로 갱신
- Phase 6 정적 계약 테스트와 Chrome smoke를 Repository quality gate에 추가

## Phase 7 — 초기 로딩·런타임·출시 안정성 · 완료

### 공개 화면 첫 렌더
- 홈·로그인·이용안내·약관 등 승인 보호가 필요 없는 화면에서 기존 최대 1.8초의 인위적인 부트 커튼 제거
- 공개 화면은 즉시 표시하고 런타임 보조 스크립트는 첫 paint 이후 로드하도록 분리
- 공개 화면용 부트 가드와 런타임 로더를 실제 Headless Chrome에서 각각 검증
- Phase 7 Chrome 계약은 공개 화면 준비가 700ms를 넘지 않도록 회귀 방지 기준 설정

### 보호 화면 승인 게이트 강화
- PDF·PDF 검사·디자인·표지·문서·이미지 도구를 보호 런타임 화면으로 명시적으로 분류
- 런타임 보조 스크립트 로더가 보호 화면의 `ProgramStudioBoot.reveal()`을 호출해 승인 확인보다 먼저 잠금을 해제할 수 없도록 수정
- 보호 화면은 `ProgramAccessReady`가 성공한 경우에만 부트 가드가 화면을 공개하도록 책임 분리
- 보조 모듈 로딩 지연이나 실패가 접근 승인 결과를 바꾸지 않도록 구성

### 레거시 서비스워커·캐시 정리
- 역사적 호환을 위해 `js/sw-register.js` 파일명은 유지하되 실제 서비스워커를 새로 등록하지 않는 런타임 로더임을 코드에 명시
- 기존 브라우저에 남아 있는 서비스워커 등록은 `getRegistrations()`를 통해 해제
- `program-studio-*` 레거시 Cache Storage 데이터는 정리
- 현재 참조 여부가 확실하지 않은 소스 파일은 이름만 보고 삭제하지 않고, 참조가 확인되는 호환 경로는 유지

### 캐시 정책
- Phase 7에서는 공통 UI 파일 자체를 변경하지 않아 `20260828-3` 캐시 버전을 그대로 유지
- 모든 런타임 자산이 완전히 버전 고정됐다는 보장이 없는 상태에서 전역 `immutable` 캐시를 강제로 적용하지 않음
- 최신 스크립트가 오래된 캐시에 고정되는 위험보다 현재의 재검증 정책을 유지하는 쪽을 선택

### 회귀 테스트 정리
- 오래된 모바일 안내 테스트가 보호 경로 판별 문자열까지 금지하던 과도한 계약을 발견
- 모바일 안내 스크립트가 실제로 로드되는 PDF 블록 범위만 검사하도록 테스트 의도를 정확히 수정
- 제품 코드를 약화시키지 않고 기존 PDF 전용 모바일 안내 계약과 새 보호 경로 판별을 동시에 유지

- Phase 7 런타임 로더 public-first-paint Chrome smoke
- 보호 화면에서 런타임 로더가 승인 잠금을 해제하지 못하도록 정적 계약 검사
- 이미지 Pro 예상 용량 테스트와 실제 인코딩 테스트를 분리해 headless Chrome 비결정성 제거
- 무한 `setInterval` 기반 보정 금지
- 핵심 렌더·저장·출력 함수 대체 금지 계약 유지
- Backend regression / JavaScript syntax / inline JS / JSON / static path / Firebase rules 검증 유지

## 현재 완료 상태

Phase 1~7의 UX/UI 개편, 모바일·접근성 정리, 레거시 진입 경로 호환, 공개 화면 초기 렌더 최적화와 보호 화면 접근 게이트 강화를 완료했다. 편집기의 PDF/디자인/문서/이미지 핵심 처리 엔진은 유지하면서 사용자 흐름과 보조 UI, 런타임 로딩 책임을 공통 레이어로 정리했다.

최종 제품 코드 기준 Repository quality gate에서는 Backend regression, Frontend/static checks, Phase 5·6·7 Chrome smoke, PDF·디자인·문서·이미지 browser smoke, Firebase rules 검사가 모두 통과했고 Firebase PR 미리보기 배포 및 사용자 경로 검증도 성공했다.

- 실제 운영 환경에서 Lighthouse/Core Web Vitals와 사용자 체감 지표를 측정해 수치 기반 최적화
- 모든 런타임 자산 URL의 버전 고정을 완료한 뒤 장기 캐시/immutable 적용 여부 검토
- 요청 수와 초기 전송량 예산을 정하고 홈·편집기별 자산 번들 또는 조건부 로딩 추가 최적화
- `sw-register.js` 역사적 파일명을 새 런타임 로더 이름으로 옮기려면 HTML·배포·회귀 계약을 포함한 별도 호환 마이그레이션으로 진행
- 더 이상 참조되지 않는 레거시 실험 파일은 저장소 전체 사용처가 0개임을 확인한 뒤 단계적으로 제거
- 신규 프로그램 추가 시 공통 디자인 토큰·작업 흐름·접근성·부트 계약을 재사용

## 완료 기준

- 주요 동작의 최소 클릭 수 감소
- 데스크톱과 모바일에서 핵심 기능 접근 가능
- 10px 미만의 필수 조작 텍스트 최소화
- 키보드만으로 주요 화면 탐색 가능
- 패널 접기 후 캔버스/미리보기 영역 즉시 확장
- 모든 화면에서 동일한 버튼·입력·상태 표현 규칙 사용
- 공개 화면은 승인 부트 타임아웃을 기다리지 않고 첫 화면 표시
- 보호 화면은 승인 성공 전 런타임 보조 코드로 잠금 해제되지 않음
- 기존 PDF/디자인/문서/이미지 출력 기능 회귀 테스트 유지
- UX 개선과 함께 발견된 오류가 자동 테스트로 재발 방지됨
