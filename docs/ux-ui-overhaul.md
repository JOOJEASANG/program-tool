# Program Studio UX/UI 전면 개편

## 목표

기능 처리 로직은 보존하면서 사용자가 처음 진입한 순간부터 결과 파일을 저장할 때까지 화면 구조, 정보 위계, 조작 밀도, 모바일 대응, 접근성을 하나의 제품 경험으로 통일한다. 개편 중 발견되는 실제 오류, 상태 불일치, 단축키 충돌과 회귀 테스트 문제도 함께 수정한다.

## 전체 진단

### 1. 화면마다 디자인 규칙이 다름
홈, 로그인, 관리자, PDF 편집기, PDF 검사, 디자인 편집기, 문서 편집기, 이미지 편집기가 각각 별도 색상·간격·버튼 크기·모서리·그림자 규칙을 사용한다.

### 2. 편집기 조작부의 글자와 터치 영역이 작음
특히 디자인 편집기에는 8~10px 수준의 설명·필드·상태 텍스트가 많고, 문서/이미지 편집기도 기능이 늘수록 왼쪽 패널 밀도가 높아지는 구조다.

### 3. 작업영역 확보와 빠른 이동이 어려움
편집기 왼쪽 패널이 항상 작업영역을 차지하고, 다른 도구로 이동하려면 홈을 거쳐야 하는 경우가 많다.

### 4. 기능 중심 배치라 초보 사용자가 작업 순서를 알기 어려움
PDF, 디자인, 문서, 이미지 편집기는 기능은 많지만 어떤 순서로 사용해야 하는지 한눈에 보이지 않는다.

### 5. 스타일과 보정 코드가 분산됨
여러 HTML/CSS/JS에 화면 보정 규칙이 분산되어 있고 오래된 실험 코드도 일부 남아 있어 새 기능을 붙일 때 회귀 위험이 있다.

## Phase 1 — 공통 UX 기반 · 완료

- 공통 색상, 여백, 모서리, 그림자, 포커스 규칙 추가
- 홈 카드와 내비게이션 가독성 개선
- 로그인 화면 데스크톱 2단 레이아웃
- 관리자 카드·메트릭·입력창 밀도 정리
- PDF/디자인/문서/이미지 편집기 기본 가독성 개선
- 편집기 `작업 패널` 접기/펼치기 및 상태 기억
- `Ctrl/Cmd + K` 전역 빠른 실행
- 입력 중 빠른 실행 단축키가 편집을 방해하지 않도록 충돌 방지
- 중첩 `/index.html` 경로를 홈으로 잘못 판별하던 오류 수정
- 키보드 포커스 표시와 `prefers-reduced-motion` 대응

## Phase 2 — PDF 편집기 작업 흐름 · 완료

- `파일 → 페이지·배치 → 꾸미기 → 출력` 4단계 흐름
- 기본 기능과 고급 설정 분리
- 출력 직전 페이지 수·용지·방향·N-up 요약
- 최종 PDF 저장 영역 하단 고정
- 런타임 모듈 실패/처리 오류 표시 및 `미리보기 재생성 / 새로고침 / 닫기` 복구
- 썸네일의 잘못된 `클릭=제외` 안내를 실제 동작인 `클릭=미리보기 이동`으로 수정
- compact shell 로딩 순서에 따라 패널 접기 버튼이 사라질 수 있던 경쟁 조건 수정
- 명시적 workflow `refresh()`는 즉시 반영하고 일반 상태 변경만 배치 갱신하도록 정리
- 기존 PDF 렌더·저장 함수는 교체하지 않음

## Phase 3 — 디자인 편집기 작업 흐름 · 완료

- `구성 → 편집 → 정리 → 출력` 4단계 흐름
- 기존 빠른 구성, 선택 요소 편집, 스마트 정리, 인쇄 품질·안전 검사와 연결
- 최종 PNG/PDF 출력 영역을 항상 찾기 쉬운 위치로 고정
- 런타임 진단 상태와 자동 저장 상태를 작업 흐름에서 바로 확인
- `고급 도구`와 선택 요소 `세부 설정`이 같은 저장 키를 사용해 서로 열림/닫힘 상태를 덮던 오류 수정
- 정상적인 취소 작업이 런타임 오류로 기록되는 문제 필터링
- 단계 클릭 후 활성 표시가 늦게 변경되던 UX 지연 수정
- 기존 300DPI 출력 및 최종 인쇄검사 파이프라인은 그대로 사용

## Phase 4 — 문서·이미지 편집기 작업 흐름 · 완료

### 문서 편집기
- `시작 → 작성 → 검토 → 출력` 4단계 흐름
- 현재 단어 수·글자 수·A4 방향·자동 저장 상태를 한 카드에서 표시
- 자동 저장 실패/경고 상태를 즉시 표시
- 사이드바 하단에 `지금 저장 / 인쇄·PDF 저장` 고정 작업 영역 추가
- 새 출력 UI는 기존 `saveNowBtn`, `printBtn`, `DocumentEditorApp` API를 그대로 재사용
- 기존 본문 편집·표·이미지·자동 저장·인쇄 로직을 교체하지 않음

### 이미지 편집기
- `불러오기 → 자르기·크기 → 보정·배경 → 저장` 4단계 흐름
- 이미지 크기·작업 횟수·오류 상태를 상단 흐름 카드에서 확인
- 저장 설정 영역을 하단 고정하고 현재 크기·형식·품질 요약 표시
- 오류 발생 시 `다른 이미지 열기 / 원본 복원`으로 기존 기능을 바로 재사용
- 숫자/설정 입력창에서 `Ctrl/Cmd+Z`가 이미지 전체 실행취소로 전달되던 단축키 충돌 방지
- PNG/JPEG/WebP 출력 및 배경 제거·자르기 핵심 함수는 교체하지 않음

## Phase 5 — 홈·관리자·PDF 검사 · 완료

### 홈
- 실제 사용 가능한 핵심 도구 5종을 `바로 작업 시작` 영역에 모아 표시
- 프로그램명·작업명 검색
- 즐겨찾기와 최근 사용 도구를 브라우저에 기억
- `/` 키로 홈 검색에 즉시 포커스
- 기존 카테고리/프로그램 카드 렌더링은 그대로 유지

### 관리자
- 대시보드 `최근 가입 회원`은 읽기 전용으로 변경해 실수로 승인/중지하는 위험 제거
- 회원 목록에 선택 체크박스와 화면 전체 선택 추가
- 다중 회원 승인·중지·FREE·PRO 변경 지원
- 일괄 변경 전 대상 인원 확인창 표시
- 개별 `이용 중지`도 확인 후 실행
- 기존 회원 목록 렌더링과 Firestore 데이터 구조는 교체하지 않음

### PDF 인쇄 검수
- 검사 결과를 `문제 → 확인 필요 → 정상` 순으로 자동 정렬
- 전체/문제/확인/정상 개수 표시 및 즉시 필터링
- 문제 카드와 확인 카드의 시각 우선순위 강화
- 기존 검사/보안/도구 처리 함수는 교체하지 않음

### 배포 안정성
- 공통 UX 자산 캐시 버전을 `20260828-2`로 갱신해 기존 브라우저에서도 최신 UI를 다시 받도록 처리
- Phase 5 홈·관리자·PDF 검사 전용 Chrome smoke를 품질 게이트에 추가

## 회귀 방지

- PDF workflow 정적 계약 및 Chrome smoke
- 디자인 workflow 정적 계약 및 Chrome smoke
- 문서 workflow Chrome smoke
- 이미지 workflow Chrome smoke
- Phase 5 홈·관리자·PDF 검사 Chrome smoke
- 이미지 Pro 예상 용량 테스트와 실제 인코딩 테스트를 분리해 headless Chrome 비결정성 제거
- 무한 `setInterval` 기반 보정 금지
- 핵심 렌더·저장·출력 함수 대체 금지 계약 유지
- Backend regression / JavaScript syntax / inline JS / JSON / static path / Firebase rules 검증 유지

## Phase 6 — 남은 화면·레거시 경로·최종 접근성

다음 단계에서 진행한다.

- 책표지제작 전용 화면 작업 흐름 정리
- 로그인/승인대기/약관·개인정보 화면의 최종 시각 통일
- `tools/` 레거시 진입 경로와 현재 편집기 UX 기능 연결 일관성 점검
- 모바일 360~480px에서 관리자·편집기 조작 밀도 최종 점검
- 키보드 포커스 순서, 제목 구조, aria 상태 최종 점검
- 오래된 보정/실험 파일 중 현재 런타임에서 사용하지 않는 코드 목록화 및 안전한 정리 계획 수립

## 완료 기준

- 주요 동작의 최소 클릭 수 감소
- 데스크톱과 모바일에서 핵심 기능 접근 가능
- 10px 미만의 필수 조작 텍스트 제거
- 키보드만으로 주요 화면 탐색 가능
- 패널 접기 후 캔버스/미리보기 영역 즉시 확장
- 모든 화면에서 동일한 버튼·입력·상태 표현 규칙 사용
- 기존 PDF/디자인/문서/이미지 출력 기능 회귀 테스트 유지
- UX 개선과 함께 발견된 오류가 자동 테스트로 재발 방지됨
