# PDF 편집기 활성 런타임 기준

기준일: 2026-08-03

## 운영 원칙

PDF 편집기는 2026년 7월 20일 정상 동작본을 기준으로 복원한 뒤, 필요한 기능만 현재 구조에 맞춰 작은 단위로 통합한다. 과거처럼 여러 보조 파일이 같은 전역 함수를 반복 감싸거나 주기적으로 감시하는 구조는 다시 활성화하지 않는다.

## 활성 루트 모듈 8개

`js/pdf-editor/loader.js`가 다음 파일만 순서대로 불러온다.

1. `font-render-fix.js`
2. `upload-fix.js`
3. `live-preview.js`
4. `layout-export.js`
5. `page-count-hint.js`
6. `nup-helper.js`
7. `preview-row-default.js`
8. `divider-helper.js`

## PDF 편집기 경로 전용 보조 스크립트

`js/sw-register.js`는 PDF 편집기 경로에서 다음 경량 스크립트를 각각 한 번만 순서대로 불러온다.

- `crop-marks.js`: 재단선·도련 작업영역, 사이드바 고정, 개별 여백 마주보기, 문서 오버레이 위치 보정
- `save-operation.js`: 저장 설정 최종 확인, API 진행률 표시, 현재 저장 작업 취소
- `save-recovery.js`: 저장 시작 체크포인트, 저장 중 편집 잠금, 실패 시 자동 복구

`save-operation.js`는 기존 API가 제공하는 준비·업로드·서버 처리·다운로드·완료 콜백을 표시하고, 활성 저장 작업의 `AbortSignal`만 전달한다. 취소 시 기존 API가 업로드 작업과 요청을 중단하고 임시 Storage 파일을 정리한 뒤 저장 버튼 상태를 복구한다.

`save-recovery.js`는 `PdfOperationManager`의 공개 연결점만 사용한다. 저장 시작 시 페이지 순서와 페이지별 설정, 원본 파일 참조, 간지 내용, 개별 여백, 머리말·꼬리말, 페이지번호, 재단선·도련 설정을 메모리 체크포인트로 보존한다. 저장 중에는 업로드·페이지 편집·설정 변경을 잠그되 미리보기 스크롤과 작업 취소는 유지한다. 생성 실패가 확인되면 체크포인트를 복원하고 미리보기를 다시 요청한다. `apiProcessPdf`, `fetch`, 미리보기·출력 렌더 함수는 대체하지 않는다.

## 현재 통합 완료 기능

- 대용량 업로드와 실패 롤백
- 미리보기 요청 직렬화와 제한 미리보기
- 썸네일 클릭 이동과 우클릭 숨김
- 다중 선택, 일괄 회전·숨김·표시·복제·이동·삭제
- 실행 취소·다시 실행
- 파일별·페이지별 N-up과 소책자 안내
- 출력면별 원본 페이지 표시
- 고급 간지 편집
- 좌·우·상·하 개별 여백과 양면 마주보기
- 머리말·꼬리말·페이지번호의 비대칭 좌우 여백 반영
- 페이지번호 공간 자동 확보의 미리보기·최종 PDF 동기화
- 재단선과 0~15mm 도련 작업영역의 미리보기·저장·세션 복원
- PDF 저장 전 파일·페이지·용지·N-up·여백·문서 요소·재단선·도련 설정 최종 확인
- PDF 저장 준비·업로드·서버 생성·다운로드 진행률 표시
- 현재 PDF 저장 작업 취소, 업로드·요청 중단, 임시파일 정리, 저장 버튼 상태 복구
- 저장 실패 시 작업 시작 체크포인트 자동 복원과 미리보기 재생성

도련 단계는 원본 그림이나 배경을 자동으로 확대하지 않는다. 원본 PDF에 도련 이미지가 없으면 완성 규격 밖의 확보 영역은 흰색으로 남는다.

## 과거 파일 비활성 유지

다음 파일은 저장소에 남아 있으나 현재 운영 경로에서는 불러오지 않는다.

- `page-number-auto-reserve.js`
- `page-number-auto-reserve-layout-v2.js`
- `page-number-preview-parity.js`
- `operation-progress-summary.js`

페이지번호 관련 과거 파일의 필요한 기능은 현재 `layout-export.js`에 통합돼 있다. 과거 `operation-progress-summary.js`는 전체를 활성화하지 않고 저장 확인·진행률·취소·복구 기능을 현재 경량 모듈로 나눠 통합했다.

완료 순서:

1. 저장 전 설정 확인
2. 업로드·서버 처리·다운로드 진행률
3. 작업 취소와 버튼 상태 복구
4. 실패 후 편집 상태 복구

## 비활성 유지 대상

다음 유형의 과거 보조 래퍼는 현재 안정 구조와 충돌 가능성이 있어 활성화하지 않는다.

- 별도 미리보기 컨트롤러와 중복 도킹 보정
- 주기적 무결성 감시
- 전역 렌더 함수의 반복 래핑
- `setInterval` 기반 DOM 보정
- 현재 모듈에 이미 통합된 기능의 중복 구현

## 단계 통과 조건

각 기능 단계는 별도 PR로 진행한다.

1. 정적·백엔드·프런트엔드 회귀 검사 통과
2. 활성 루트 모듈 8개 유지
3. PDF 경로 전용 보조 스크립트 단일 로드와 순서 고정
4. Firebase PR 미리보기 배포 성공
5. 사용자 경로 스모크 검사 성공
6. 저장 성공·취소·실패별 체크포인트 정리 확인
7. 실패 후 페이지·설정·미리보기 복원 확인
