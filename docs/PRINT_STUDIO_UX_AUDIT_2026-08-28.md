# Program Studio 인쇄·출력 UX 진단 및 개선 방향

작성일: 2026-08-28

## 1. 제품 방향

Program Studio는 범용 문서 사이트보다 **인쇄·출력 직전 실무에서 반복되는 작업을 빠르게 끝내는 전문 도구**에 집중하는 편이 경쟁력이 높다.

핵심 흐름은 다음 네 단계로 단순화한다.

1. **디자인 제작** — 표지, 포스터, 전단, 초대장·안내장, 리플렛
2. **PDF 편집·인쇄배치** — 페이지 정리, 여러 PDF 결합, N-up, 소책자, 간지, 페이지 번호
3. **인쇄 전 검사·변환** — 규격, DPI, 폰트, 도련, 여백, PDF 유틸리티
4. **이미지 작업** — 자르기, 리사이즈, 기본 보정, 배경 제거, 출력용 이미지 저장

기능 수를 늘리기보다 사용자가 파일을 넣고 결과물을 저장할 때까지 **같은 개념과 같은 조작 방식**을 유지하는 것이 우선이다.

## 2. 현재 구조에서 가장 큰 UX 문제

### P0-1. 초대장과 리플렛의 상태가 섞임

기존 제품 메뉴에는 `초대장·안내장`이 별도 항목으로 보이지만 실제 전환 시 내부적으로 `leaflet2` 프로젝트를 먼저 열고, 이후 `printProductMode=invitation`을 덮어쓰는 구조였다.

이 때문에 다음과 같은 불일치가 발생할 수 있었다.

- 초대장을 선택했는데 일부 제목이나 메뉴에서 리플렛으로 표시
- 자동 저장 범위나 문서 상태가 리플렛 기준으로 분류될 가능성
- 제품 식별 로직마다 `designMode`와 `printProductMode` 중 어떤 값을 먼저 보는지가 달라짐
- 후속 기능이 추가될수록 초대장/리플렛 구분 오류가 재발하기 쉬움

### 개선

초대장을 `invitation-a4`라는 **독립 프리셋 + 독립 designMode**로 승격한다.

`designMode=invitation`을 문서 종류의 1차 기준으로 사용하고, 접지 위치·접지 방향·상하 뒤집기 같은 생산 옵션은 그 아래 속성으로 둔다.

---

### P0-2. PDF 여러 파일 작업에서 업로드 전에 연속/비연속을 선택해야 함

기존 PDF 편집기는 업로드 모드가 다음과 같이 전역 상태로 되어 있다.

- 새 파일
- 연속 추가
- 비연속 추가

하지만 실제 사용자는 파일을 추가하면서 매번 관계를 미리 판단해야 한다. 이미 파일을 올린 뒤 관계를 바꾸려면 다시 업로드 동선을 의식해야 한다.

### 개선

업로드와 파일 관계 설정을 분리한다.

- 첫 파일: 자동으로 새 작업 시작
- 이후 파일: 무조건 현재 작업에 계속 추가
- 파일 제목 경계에서 `연속` / `새 묶음`을 즉시 전환
- 여러 PDF를 한 번에 선택 가능
- 파일을 다 올린 다음 출력 묶음만 수정 가능

즉, **파일을 먼저 넣고 관계를 나중에 정한다.**

이 방식은 출력소에서 여러 교재·문서·간지를 한 작업에 올려놓고 묶음을 정리하는 흐름과 더 잘 맞는다.

---

### P0-3. 표지 전환만 편집기 전체가 다시 로드됨

다른 디자인 종류는 같은 편집기 안에서 문서 상태만 바꾸는데, 기존 제품 메뉴의 `표지`는 상위 iframe에 메시지를 보내 전체 `/design-editor/general`을 다시 로드했다.

이미 `DesignEditorCoverModeBridge.activateCoverInPlace()`라는 현재 편집기 내 전환 기능이 존재했지만 제품 메뉴가 이를 사용하지 않았다.

### 개선

제품 메뉴의 표지 클릭을 캡처해 현재 편집기에서 `cover-a4` 프로젝트로 즉시 전환한다.

- iframe 전체 재로드 제거
- 인증/공통 스크립트 재실행 제거
- 기존 작업 저장 후 표지 모드 전환
- 표지 가이드·책등 설정만 다시 동기화

## 3. 화면 디자인 문제

현재 기능 자체는 상당히 많지만, 여러 시기에 추가된 스타일과 런타임 보조 스크립트가 겹쳐 화면의 밀도가 높다.

특히 디자인 편집기의 일부 제품 설정은 7~8px 수준의 텍스트를 사용하고 있어 데스크톱에서도 읽기 어렵다. 전문 프로그램 느낌은 기능을 많이 노출하는 것보다 **정보 계층이 분명하고 조작 위치가 예측 가능할 때** 생긴다.

### 권장 최소 UI 기준

- 기본 본문/설정 글자: 12~13px
- 보조 설명: 10~11px 이하로 내려가지 않음
- 주요 버튼 높이: 34~40px
- 입력/선택 컨트롤: 32px 이상
- 카드 모서리: 한 화면에서 2~3개 규격만 사용
- 강조색: 기능별 여러 색 대신 주색 1개 + 상태색
- 아이콘은 장식보다 작업 의미가 있는 경우에만 사용

이번 1차 수정에서는 초대장/리플렛 제품 설정의 폰트와 입력 높이를 우선 키웠다.

## 4. 디자인 제작 화면 권장 구조

### 상단 — 문서 명령바

항상 보이는 항목만 둔다.

- 홈 / 작업 종류
- 문서명 + 규격
- 실행 취소 / 다시 실행
- 저장 상태
- 미리보기
- 인쇄용 PDF/PNG 저장

현재처럼 제품 메뉴와 선택 속성 도구가 여러 줄로 겹치지 않도록 한다.

### 왼쪽 — 제작 도구

고정 탭 5~6개만 둔다.

- 템플릿/빠른 시작
- 텍스트
- 이미지
- 도형/배경
- 구성요소
- 문서/접지 설정

탭을 누르면 그 기능의 패널만 열린다.

### 가운데 — 캔버스

가장 넓은 영역으로 유지한다.

- 작업면
- 도련
- 안전여백
- 접지선
- 정렬 가이드
- 선택 영역
- 실제 출력 크기 표시

하단에는 `맞춤 / 50% / 100% / 확대 / 축소` 정도의 줌 컨트롤을 고정한다.

### 오른쪽 — 선택 속성

선택한 대상이 있을 때만 관련 속성을 표시한다.

예:

- 글자 선택 → 글꼴/크기/굵기/행간/정렬
- 이미지 선택 → 자르기/맞춤/DPI/투명도
- 여러 개 선택 → 정렬/간격/그룹
- 아무것도 선택하지 않음 → 문서/배경 속성

이렇게 하면 왼쪽 패널을 계속 길게 스크롤하는 문제를 크게 줄일 수 있다.

## 5. PDF 편집 화면 권장 구조

PDF 편집기는 기능보다 **파일 → 페이지 → 출력 설정**의 관계가 보이는 것이 중요하다.

### 왼쪽 상단

`PDF 추가` 버튼 하나만 크게 둔다.

업로드된 파일은 파일별 헤더로 표시한다.

예:

```text
01. 교재_본문.pdf       [연속]
   1  2  3  4 ...

02. 간지.pdf           [새 묶음]
   1

03. 부록.pdf           [연속]
   1  2  3 ...
```

여기서 `연속 / 새 묶음`을 클릭하면 즉시 변경한다.

### 왼쪽 페이지 목록

- 클릭: 페이지 선택/미리보기 이동
- 우클릭: 숨기기, 회전, 빈 페이지/간지 삽입 등
- 드래그: 순서 변경
- 파일 접기/펼치기
- 편집 페이지 번호 및 원본 페이지 번호 이동

### 가운데

실제 결과 PDF를 보여주는 미리보기 전용 공간으로 둔다.

### 오른쪽

출력 설정을 작업 순서대로 묶는다.

1. 용지
2. 배치(N-up)
3. 소책자/양면
4. 여백/간격
5. 워터마크/머리말/페이지 번호
6. 인쇄 전 검사
7. 저장

현재 존재하는 기능은 유지하되 화면 노출 순서를 이 흐름에 맞춘다.

## 6. 홈 화면 정보 구조

현재 `home-professional-suite.js`에서 기존 여러 카테고리를 런타임에 지우고 인쇄·출력용 4개 프로그램으로 다시 구성하고 있다. 제품 방향은 맞지만, 홈이 먼저 렌더링된 뒤 다시 덮어쓰는 구조는 장기적으로 제거해야 한다.

최종 홈은 처음부터 다음 4개만 1차 메뉴로 렌더링하는 것이 좋다.

- 디자인 제작
- PDF 편집·인쇄배치
- PDF 검사·변환
- 이미지 작업

그 아래 `인쇄 작업 빠른 시작`을 둔다.

```text
디자인 제작 → PDF 편집·인쇄배치 → 인쇄 전 검사 → 결과 저장
```

사용자는 프로그램 이름보다 **무슨 결과를 만들 수 있는지** 보고 들어오게 해야 한다.

## 7. 코드 구조 개선 우선순위

### 1단계 — 현재 불편 제거

- [x] 초대장 독립 프리셋/모드
- [x] 초대장과 리플렛 상태 분리
- [x] PDF 업로드 모드 반복 클릭 제거
- [x] 파일 경계에서 연속/새 묶음 전환
- [x] 표지 전환 시 iframe 전체 재로드 제거
- [x] 제품 설정 글자/컨트롤 가독성 1차 개선

### 2단계 — 디자인 편집기 UI 통합

- [ ] 제품 메뉴를 한 군데의 `PRODUCTS` 설정으로 통합
- [ ] `designMode`, `printProductMode`, `presetId` 중 문서 종류 기준을 하나로 정리
- [ ] 좌측 도구 / 중앙 캔버스 / 우측 속성의 3영역 레이아웃
- [ ] 7~9px UI 텍스트 제거
- [ ] 선택 컨텍스트에 따라 속성 패널 자동 변경
- [ ] 표지/포스터/전단/초대장/리플렛의 문서 전환을 모두 무재로딩 방식으로 통일

### 3단계 — PDF 편집기 구조 분리

현재 `pdf-editor/index.html`에 상태, 파일 업로드, 썸네일, 렌더링, 세션, UI 이벤트가 많이 함께 들어 있다.

다음 단위로 분리하는 것이 좋다.

- `state.js`
- `import.js`
- `file-groups.js`
- `page-list.js`
- `preview.js`
- `output-settings.js`
- `save.js`

후속 `*-fix.js`가 원본 함수를 계속 덮어쓰는 구조도 단계적으로 없앤다.

### 4단계 — 홈/공통 셸 정리

- [ ] 홈 카테고리 런타임 덮어쓰기 제거
- [ ] 공통 헤더/버튼/입력/모달 디자인 토큰화
- [ ] 각 프로그램의 상단바 높이와 주요 CTA 위치 통일
- [ ] 로딩은 임의 타이머보다 실제 준비 이벤트 기준으로 표시

## 8. 최종 목표

Program Studio의 기준은 "기능이 많아 보이는가"가 아니라 다음 질문으로 잡는다.

> 파일을 처음 올린 사용자가 설명을 읽지 않아도 원하는 출력 결과를 만들고, 마지막 저장 파일이 인쇄에 안전한지 확인할 수 있는가?

모든 신규 기능은 이 흐름을 단축할 때만 1차 메뉴에 노출한다.
